# ZJSY 来源验证协议 v1

## 证明范围

可信公钥内置在验证页，私钥仅存在于站点 Secret。ECDSA P-256 / SHA-256 签名证明服务签发了数据摘要。图像提供的任意公钥不被信任。

服务公开，不核验调用者、证件真伪或网页执行过程。不得把签名理解为本站审核过内容，或一定由未经修改的前端完成全部渲染。

## 签名绑定

二进制正文包含版本、导出尺寸、主体区域、随机 nonce、内容 SHA-256、64 字节灰度特征、用途、有效期和署名，全部在浏览器中组成。只向 /api/sign 发送正文 SHA-256，服务签名以下 UTF-8 消息：

    ZJSY-site-proof/v1
    <keyId>
    <issuedAt Unix seconds>
    <body SHA-256 lowercase hex>

服务仅返回公钥 ID、签发时间和 64 字节签名，不保存摘要。客户端验证服务签名后再导出。

内容摘要覆盖图像顶部到验证底边之前的 RGBA，包括主体、可见水印和白边声明。蓝色最低位归零，为隐写预留；其余位全部绑定。验证底边不纳入内容摘要，避免二维码和隐写造成自引用循环。

## 两个隐写位置

- 主体：基于凭据摘要生成遍历顺序，分散写入蓝色最低位，重复两份码字，每像素最多变化一个蓝色色阶。
- 白边：低频 DCT 系数符号编码，重复两份相同码字，与 JPEG 的 8 像素网格对齐。
- RS(255,191)：GF(256)，原始多项式 0x11d，64 个校验字节，每份理论上最多纠正 32 个错误字节。纠错后还要检查 CRC 和签名数据一致性。

隐写包含正文摘要、公钥 ID、签发时间和签名，必须与二维码完整凭据相同。仅粘贴二维码或白边不会使替换主体通过严格摘要检查。

## 二维码与隐私

完整凭据以 Base64URL 放入 VERIFY_URL#p=...。片段不在 HTTP 请求中，验证页本地解析并清理当前历史条目。二维码识别和签名验证不请求服务器。

用途、有效期、署名是二维码明文，会随照片分享；设备或扫码程序可能保存网址，网站不控制外部软件。

## 压缩边界

PNG 可保留严格摘要。JPEG 和缩放改变像素，也可能破坏主体最低位；白边 DCT 与纠错有助于恢复凭据。严格摘要不匹配时仅比较已签名的 8×8 灰度均值：

- 宏观近似显示警示，绝不显示严格通过。
- 特征不是安全哈希，细微修改或刻意构造的相似图可能近似。
- 裁剪、透视、强缩小、重拍和严重压缩可能无法恢复，不得判为通过。

## 密钥与部署

ZJSY_SIGNING_PRIVATE_KEY 是 Base64 PKCS#8 私钥 Secret；ZJSY_SIGNING_KEY_ID 对应公钥表。Worker 不记录请求、不使用数据存储，应用关闭 observability；平台仍可能处理常规请求元数据。

生成脚本仅将私钥写入仓库外。公钥、Secret 和 ID 应配套更新；正常轮换保留旧公钥，私钥泄露时撤销旧公钥。
